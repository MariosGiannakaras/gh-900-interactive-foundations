# Module 5 — Introduction to GitHub Copilot

Official Microsoft Learn module: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/>

This module maps **1:1 to all 7 official units** and also flags newer GH-900 terminology where the exam blueprint has evolved beyond older Copilot descriptions.

## Learning objectives

After this module you should be able to:

- explain what GitHub Copilot is and where it appears;
- recognize inline suggestions, chat, inline chat, code explanations, test generation, CLI assistance, PR summaries/review assistance, Spaces, and agent-style workflows;
- distinguish the purpose of Copilot Free, Pro/Pro+, Business, and Enterprise at a conceptual level;
- interact with Copilot through editor suggestions, chat, commands, comments-to-code, and alternatives;
- set up and configure Copilot in VS Code;
- troubleshoot common extension/network issues;
- evaluate generated code instead of treating AI output as automatically correct;
- complete a Copilot-assisted coding exercise even though the course cannot prove which keystrokes were generated by AI.

## Unit 1 — Introduction

Official unit: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/1-introduction>

GitHub Copilot is an AI-powered development assistant integrated into GitHub and supported development environments. It can help generate, explain, refactor, debug, document, and test code.

Copilot is an assistant, not an authority. The developer remains responsible for reviewing security, correctness, licensing/context, performance, and suitability of generated output.

## Unit 2 — GitHub Copilot, your AI pair programmer

Official unit: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/2-github-copilot-your-ai-pair-programmer>

### Editor assistance

Copilot began as context-aware code completion but now spans more of the software lifecycle.

Typical capabilities include:

- code completions;
- comment-to-code generation;
- code explanations;
- refactoring suggestions;
- test generation;
- documentation generation;
- debugging help;
- project/repository questions through chat.

### Copilot Chat

Chat uses natural-language prompts and available code/repository context to answer questions or propose changes. Useful scenarios include:

- explain unfamiliar code;
- diagnose an error;
- design an implementation;
- generate tests;
- propose documentation;
- compare approaches.

### Pull request assistance

Depending on plan/product availability, Copilot can assist with pull-request summaries and code-review workflows. The core concept is that AI can reduce the manual effort required to summarize changes or identify review considerations; human review remains important.

### CLI assistance

Copilot can help explain commands/output and propose terminal commands or scripts. Generated shell commands should be reviewed before execution, especially commands that modify/delete data or change infrastructure.

### Copilot Spaces

Spaces provide a context-rich place for project-specific AI collaboration and can include relevant repository/project information for higher-level planning and discussion.

### Agent-style workflows

The current product family includes agentic capabilities that can perform multi-step tasks rather than only suggesting one completion. Terminology and surfaces evolve (for example coding agents/cloud agents and editor Agent Mode), but the distinguishing concept is:

- **completion/chat** primarily proposes information/code interactively;
- **agentic workflows** can plan and execute multiple related development steps under user direction and review.

For GH-900, recognize the purpose of agent-style assistance and organization policies rather than memorizing a transient UI label.

### Copilot plans

Plan names and limits change, but the Microsoft Learn module currently distinguishes:

- **Copilot Free** — limited individual usage;
- **Copilot Pro** — expanded individual capabilities/usage;
- **Copilot Pro+** — higher premium-model/request capacity for individuals;
- **Copilot Business** — organization-managed access, policy, security/privacy controls;
- **Copilot Enterprise** — enterprise-oriented GitHub integration, organizational context, and enhanced enterprise capabilities.

For certification purposes, the important distinction is **individual subscription vs centrally administered organizational/enterprise service**.

### Organizational controls

Business/Enterprise environments can centrally govern availability and policy. Admins may control access to features/models, public-code matching/filtering behavior, and other organization-level Copilot settings according to current product capabilities.

## Unit 3 — Interact with Copilot

Official unit: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/3-interacting-with-copilot>

### Inline suggestions

As you type, Copilot can display a completion ahead of the cursor. You can accept, reject, keep typing, or cycle through alternatives.

Inline completion is especially useful for boilerplate, repetitive code, predictable transformations, and implementing intent expressed by nearby code/comments.

### Command palette

VS Code's command palette exposes Copilot actions and is useful when you want an explicit operation instead of waiting for a completion.

### Chat

Chat accepts natural-language requests and can use code context. Good prompts provide:

- goal;
- relevant constraints;
- language/framework;
- expected inputs/outputs;
- edge cases;
- desired testing or error handling.

### Inline chat

Inline chat targets the code near the current selection/cursor. It is useful for localized explanations and transformations.

### Slash commands / action shortcuts

Copilot environments may provide shortcut commands for common intents such as explanation or tests. Exact command names can evolve; understand the intent rather than assuming every editor/version exposes identical commands.

### Comments to code

A clear natural-language comment can act as a prompt for an implementation suggestion. The quality of context affects the quality of suggestions.

### Multiple suggestions

Copilot may offer alternative implementations. Comparing alternatives is important because the first generated approach is not automatically the best one.

### Explanations and test generation

Copilot can explain selected code and generate candidate unit tests. Generated tests must be reviewed for coverage quality and correctness; a test produced by the same model that produced code should not be treated as independent proof of correctness.

### Context matters

Well-structured code, descriptive names, nearby comments, open files, repository instructions, and selected context can materially affect output relevance.

## Unit 4 — Set up, configure, and troubleshoot GitHub Copilot

Official unit: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/4-setup-configure-troubleshoot>

### Access

A user must sign in with a GitHub identity that has appropriate Copilot access. Access may come from an individual plan or be assigned by an organization/enterprise.

### VS Code setup

The normal flow is:

1. install/enable the GitHub Copilot extension/features in VS Code;
2. authenticate with GitHub;
3. ensure the account has Copilot entitlement;
4. verify Copilot is enabled for the current environment/language.

### Enable/disable behavior

Copilot completions can be enabled/disabled globally or, where supported, per language. Inline suggestion settings can also be controlled through editor settings.

### Troubleshooting

Useful troubleshooting sources include:

- VS Code extension logs;
- developer/extension log folders;
- developer tools/Electron logs when normal extension logs are insufficient;
- Copilot diagnostics collection commands;
- network/proxy/firewall configuration;
- sign-in/entitlement state;
- extension version and editor compatibility.

A common troubleshooting sequence is:

1. confirm account entitlement;
2. confirm authentication;
3. confirm extension/feature enabled;
4. inspect logs/diagnostics;
5. test network/proxy access;
6. update/reload/re-authenticate as appropriate.

## Unit 5 — Exercise: Develop with AI-powered code suggestions by using GitHub Copilot and VS Code

Official unit: <https://learn.microsoft.com/en-us/training/modules/introduction-to-github-copilot/5-exercise>

The official exercise asks the learner to use Copilot in a GitHub-hosted/VS Code environment, prompt for suggestions, and accept/review code suggestions.

Our integrated exercise uses `lab/module-05-copilot` and a small programming task.

You will:

1. open the course repository in Codespaces or VS Code;
2. confirm Copilot access if available;
3. read the task specification before coding;
4. use inline suggestion/chat/agent assistance if available;
5. implement the required behavior;
6. add tests;
7. review generated code manually;
8. record which Copilot interaction modes you used and what you rejected/changed;
9. run tests and commit the final implementation.

Because GitHub cannot reliably prove whether a human or Copilot typed a line, the engine validates the **resulting code, tests, and reflection artifact**, while the hands-on instructions require actual Copilot interaction for learners who have access.

If a learner has no eligible Copilot entitlement, the course provides a scenario-based fallback so the theory is still fully assessable without pretending AI usage occurred.
