# Source-audited additions — Module 5

## m05-u07

The module summary should leave you able to place GitHub Copilot in the development workflow rather than treat it as an autonomous authority. Copilot can provide inline completions, chat-based explanation/generation, and assistance across supported development surfaces; the developer is still responsible for reviewing generated code, checking whether it matches the stated requirement, testing it, and following the repository's normal security and review controls.

Effective use depends heavily on **context**. Clear intent, relevant files/code, constraints, expected behavior, examples, and tests make a request more useful than a vague instruction. Suggestions can be incomplete, insecure, stylistically inconsistent, or simply wrong, so accepting a plausible-looking result without understanding it is not a sound workflow.

For GH-900, also keep product/governance concepts separate from coding behavior: individual and organization/enterprise Copilot offerings can differ in administration and policy, and current GitHub experiences can expose multiple models, agent capabilities, or Agent Mode. Those features extend what Copilot can do, but do not remove the need for human review, permissions, repository policy, or ordinary software-quality checks.
