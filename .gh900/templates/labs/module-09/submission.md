# Module 9 assessment questions

## Q1
What should you normally do before contributing to an open-source repository?
- [ ] A. Ignore project documentation and open a large PR immediately.
- [ ] B. Read contribution guidance, code of conduct, license/context, and existing Issues/PRs.
- [ ] C. Ask for admin access first.

## Q2
What is a fork on GitHub?
- [ ] A. A local uncommitted change.
- [ ] B. A Git tag.
- [ ] C. A repository copy connected to an upstream repository that supports independent work/contribution workflows.

## Q3
Why keep a contribution focused?
- [ ] A. Small, related changes are easier to review, discuss, test, and merge.
- [ ] B. GitHub rejects any PR with more than one file.
- [ ] C. Focused PRs bypass review.

## Q4
What is a good way to identify contribution opportunities?
- [ ] A. Modify random files until maintainers respond.
- [ ] B. Review project Issues, labels, roadmap/discussions, documentation gaps, and maintainer guidance.
- [ ] C. Duplicate existing PRs.

## Q5
What is the role of a project license?
- [ ] A. It stores Git credentials.
- [ ] B. It creates branch protection.
- [ ] C. It states legal permissions/conditions for using, modifying, and distributing the project.

## Q6
What should a useful Pull Request description communicate?
- [ ] A. What changed, why, relevant context/testing, and links to related work when applicable.
- [ ] B. Only the contributor username.
- [ ] C. The contributor password.
