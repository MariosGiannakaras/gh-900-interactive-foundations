## Q1
What is InnerSource?

- [ ] B. Hiding the repository from all potential contributors.
- [ ] C. Removing all review requirements.

- [ ] A. Calculating billing.
- [ ] B. Managing Codespaces retention.

## Q4
Why define contribution and review expectations?
- [ ] A. To prevent every non-maintainer from reading code.
- [ ] B. To make cross-team contribution predictable, supportable, and aligned with quality/governance requirements.
- [ ] C. To eliminate the need for documentation.

## Q5
Which GitHub feature can help contributors discover and discuss potential work before code changes?
- [ ] A. Issues and Discussions, depending on the collaboration pattern.
- [ ] B. Commit object compression only.
- [ ] C. Billing reports.

## Q6
What is the healthiest InnerSource governance model?
- [ ] A. No rules and no owners.
- [ ] B. Only core maintainers may ever propose changes.
- [ ] C. Broad internal contribution with explicit ownership, review, security, documentation, and support boundaries.
