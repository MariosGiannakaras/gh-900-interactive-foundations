## Hands-on / product-comparison activities

1. Compare the GitHub account/product tiers discussed in the module and note which audience each serves.
2. Open GitHub Desktop or review its official interface/features and contrast it with the web UI.
3. Review GitHub Mobile capabilities and identify what is practical on mobile versus desktop/web.
4. Open your own Billing & licensing settings in read-only mode where available. Do not purchase or change a plan for this lab.
5. Locate documentation/examples for license usage statistics and metered usage reports; record what each report answers.

### Q1
Why does GitHub offer different account and plan types?
- [ ] A. Different plans use different Git implementations that cannot interoperate.
- [ ] B. They support different individual, team, organization, and enterprise governance/capability needs.
- [ ] C. Only Enterprise plans can contain repositories.

### Q2
Which statement best distinguishes GitHub Desktop from GitHub Mobile?
- [ ] A. Desktop is only for viewing Issues and cannot commit.
- [ ] B. Mobile replaces a local Git working copy for full development workflows.
- [ ] C. Desktop focuses on graphical local Git/repository workflows, while Mobile focuses on collaboration and repository activity on mobile devices.

### Q3
What is GitHub billing primarily concerned with?
- [ ] A. Paid plans, seats, metered services, and other billable usage associated with an account or organization.
- [ ] B. Git commit hashes.
- [ ] C. Branch naming rules only.

What can license-usage information help an administrator understand?
- [ ] A. The contents of every private commit.
- [ ] B. How assigned/consumed licenses or seats are being used across the relevant account scope.

### Q5
What is a metered usage report useful for?
- [ ] A. Replacing CODEOWNERS.
- [ ] B. Determining whether a merge conflict exists.
- [ ] C. Understanding consumption of services that are billed according to usage.

- [ ] A. Inspect settings/reports and documentation without purchasing or changing subscriptions unnecessarily.
